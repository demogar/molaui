# Theming

<DecisionsBehind foundation="Foundations/Theming" />

Can you use your own colours? Yes, at the points listed below, and on one condition: you measure
the result. Mola's contrast contract measures `tokens.css` as it ships. Once your app declares
`--accent` on its own root, that measurement no longer covers what your app paints, and nothing
in your build will notice. This page shows where to change things, what Mola still guarantees
after you do, and a worked example measured live.

## Where you can change things

| Override point | Tokens | What follows it | Before you change it |
| --- | --- | --- | --- |
| **The accent** (your brand) | `--accent`, `--on-accent`, `--accent-soft`, `--on-ink-accent` | `--selected` (selected rows, the bulk bar), `band-accent` (the band a control reveals under the pointer, the working texture), text selection, the accent badge and swatch | The pairings on the accent, its wash and the inverse panel. This is the point made for it: [ADR 0008](?path=/docs/decisions-0008-the-rojo-register--overview) gave the accent its own name so that an app can change it without repainting a layer. |
| **The faces** | `--font-ui`, `--font-display`, `--font-text`, `--font-mono` | Every component | Keep the three roles (system, reader, machine). A UI face without a `wdth` axis loses the label register, because labels are set on the width axis. |
| **The status roles** | `--danger`, `--success`, `--warn`, `--info`, with their `--ink-*` and `-soft` forms | Every status mark, badge, callout and failed state | Each one means one thing. Re-dyeing danger is allowed. Making it stop meaning danger is not. |
| **The grounds and the inks** | `--cloth*`, `--ink*`, `--keyline*` | Every pairing in the system | That is a new theme, not an override. Fork the tokens instead (see [A fork](#a-fork)). |

These are **not** override points:

- **The metrics.** Control and row heights, the spacing unit and the type scale belong to
  [density](?path=/docs/foundations-density--overview). [Versioning](?path=/docs/mola-ui-versioning--overview)
  counts them as public API, because apps lay out against them.
- **The shape.** The radius is zero and has no token to change. The ink keyline is the edge of
  every control. Its width (`--cut-w`) is a token, but at 1.5px it is what reaches 3:1 on every
  ground.
- **The layers by name** (`--rojo`, `--oro`, `--anil`, `--verde`). A component that takes
  `band="oro"` means gold, and `--oro-soft` is also the ground under warning text. Repaint `--oro`
  and every warning changes colour too. To re-brand, change the role.

## How to write an override

Put it after Mola's stylesheet, outside any `@layer`. Mola's CSS is all inside layers, so an
unlayered rule wins without `!important`. Write it on `:root, [data-theme]`, and give every colour
both themes in one `light-dark()` pair:

- **Both selectors.** A build that minifies with Lightning CSS for browsers older than Chrome 123
  and Safari 17.5 lowers `light-dark()`, and a Vite production build does by default. After that, a token changes
  theme only where it is declared. An override on `:root` alone would freeze a
  `data-theme="dark"` panel in the root's theme. Mola declares its own colours on both selectors
  for the same reason.
- **Both themes at once.** A colour declared for one theme is the colour someone forgets to check
  in the other ([ADR 0004](?path=/docs/decisions-0004-themes-with-light-dark--overview)).

## What Mola still guarantees

After an override, everything that does not depend on the colour values still holds: every state
still has a glyph and a word as well as a colour, the keyboard and focus behaviour is unchanged,
the focus ring and every control edge are still ink, and density and direction still work. What
is no longer guaranteed is the contrast of any pairing your override reaches. That one is yours
to measure, and the tables below show how.

## A worked example: Cayuco's teal instead of gold

Cayuco, the demo platform in these docs, re-brands its accent from gold to teal. It changes the
accent role, not `--oro`, so warnings stay gold. The teal is a light, saturated field like the
gold it replaces, so `--on-accent` (ink in both themes) still reads on it. The wash is mixed
thinner in the dark theme, as Mola's own gold wash is: on dark cloth, a bright colour at the light
theme's strength lifts the ground until muted ink fails on it.

<OverrideCheck preview label="Cayuco's accent, its wash mixed thinner in dark.">

```css
/* cayuco-theme.css, imported after @demogar/mola-ui/styles.css */
:root,
[data-theme] {
  --accent: light-dark(#3cbfae, #4fd1bf);
  --accent-soft: light-dark(
    color-mix(in oklab, var(--cloth-pale) 80%, var(--accent)),
    color-mix(in oklab, var(--cloth-pale) 90%, var(--accent))
  );
  --on-ink-accent: light-dark(#3cbfae, #0e5c53);
}
```

</OverrideCheck>

Each row is a pairing the system promises, measured again with the override applied. The table
also lists the pairings the override reaches only indirectly: `--selected` is not in the
override, but it is defined as `var(--accent-soft)`, so it changed too.

**Don't use one wash for both themes.** The same teal with the light theme's 80% wash in both
themes looks right in light and fails in dark. Muted ink on a selected row, the "2 of 40" beside
the id, drops to about 4:1.

<OverrideCheck label="The same teal with one wash for both themes. Muted ink fails on it in dark.">

```css
/* Don't: one mix for both themes */
:root,
[data-theme] {
  --accent: light-dark(#3cbfae, #4fd1bf);
  --accent-soft: color-mix(in oklab, var(--cloth-pale) 80%, var(--accent));
}
```

</OverrideCheck>

## A fork

To change the grounds, the inks or the layers themselves, fork the tokens rather than override
them. Edit `src/styles/tokens.css`, then run `npm test`. The contract test measures every promised
pairing in both themes and names each one that fails. `npm run tokens` then writes the same set to
`tokens/mola.tokens.json` for Figma. That way your fork is measured the way Mola is.

## Checklist

1. Change a role (`--accent`, `--danger`), not a layer (`--oro`, `--rojo`).
2. Write the override on `:root, [data-theme]`, unlayered, after Mola's stylesheet.
3. Give every colour both themes in one `light-dark()`.
4. Measure every pairing it reaches, in both themes, as the tables above do.
5. Check a selected row, a hovered control and a running task in both themes, because those are
   where the accent shows.
