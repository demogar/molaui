# Iconography

<DecisionsBehind foundation="Foundations/Iconography" />

Icons are [Lucide](https://lucide.dev) (`lucide-react`, a dependency of the package). An icon is a
second way of saying something the words already say, so in this system an icon almost never
stands alone: it sits beside a label, or it carries a label of its own that a screen reader reads.

## The set the components use

These are every Lucide icon the shipped components draw, as of this version. Reach for one of
these before adding another, and keep each to the meaning it already has here: a reader who has
learned that a counter-clockwise arrow means Retry should not meet it meaning Undo.

<IconSet />

## Sizes

An icon is sized by the control it sits in, not by the person placing it. Buttons size their own
icons with `[&_svg]:size-*`, so an icon passed to a button needs no class at all.

| Where | Size | Class |
| --- | --- | --- |
| Small button, a glyph inside a badge or a stat | 14px | `size-3.5` |
| Default and large button, menu item, field adornment | 16px | `size-4` |
| Empty state | larger, drawn by the component | — |

Icons keep Lucide's 2px stroke at these sizes. Marks that must read at a glance at 14px, the check
in a checkbox, select or menu and the plus and minus of a number input, are drawn heavier, at
2.5px to 3.5px.

## When an icon needs a label

- **Beside a word, an icon is decoration.** Mark it `aria-hidden`; the word is the accessible
  name. Button's `icon` prop does this for you.
- **Alone, an icon needs a name.** `IconButton` will not type-check without `label`, which becomes
  its `aria-label` and its native tooltip. Name the action and its object, “Copy run id”, not the
  picture, “Clipboard”.
- **An icon that carries state needs its word too.** A check or a cross is not a status. Status is
  glyph, word and colour, so a failed step shows its mark *and* says Failed.
- **If you are unsure whether people will know what it means, use a text button.** An icon-only
  control saves space only once everyone has learned it.

## One disclosure marker

Everything that expands in place uses a **plus that turns into a cross**: accordions, collapsibles,
reasoning, tool calls, agent-run steps and diff hunks. A **chevron means navigation**: a submenu, a
pager, the next month in a calendar. One marker per meaning, so a reader never has to work out
whether a chevron will take them somewhere or open something here.

    <span className="flex items-center gap-2 text-sm"><Plus aria-hidden className="size-4 rotate-45" /> Open</span>
  </div>
</Specimen>

## Direction

In a right-to-left page, icons that mean forward or back are mirrored with `rtl:-scale-x-100`:
pagination and submenu chevrons, the button arrow and the sidebar toggle. Icons that do not point
along the reading direction stay as drawn: play, the up and down trend arrows on a stat, an
external link.

## Status marks are not icons

Run and step status use **square marks drawn from the cloth vocabulary** rather than circles and
spinners: hollow for queued, the working relleno for running, filled verde for succeeded, filled
rojo with a cross for failed, hollow with a slash for cancelled. They are drawn by the system, not
taken from Lucide, and they keep their meaning in greyscale because each one also has its word.
