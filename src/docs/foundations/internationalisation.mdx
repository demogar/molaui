# Internationalisation

<DecisionsBehind foundation="Foundations/Internationalisation" />

Most of what a screen says is yours: titles, labels, the rows of a table. The components also say
some things on their own, such as a dialog's “Close”, a pager's “Previous page”, a toast's
“Dismiss” or a reasoning panel's “Thought for 4s”. Every one of those words comes from one table,
and you can replace any of them without forking a component.

## Three layers

1. **English, by default.** With nothing set, every component speaks English. An app that does not
   localise adds nothing.
2. **`MessagesProvider`, for the app.** Wrap the root once with your words and your locale. Any key
   you leave out keeps its English.
3. **A component's `messages` prop, for one place.** It wins over the provider, for the one dialog
   whose close button should say “Close settings”.

```tsx
import { MessagesProvider, ToastProvider } from '@demogar/mola-ui'
import es from './messages/es.json'

export function App({ children }) {
  return (
    <MessagesProvider locale="es-PA" messages={es}>
      <ToastProvider>{children}</ToastProvider>
    </MessagesProvider>
  )
}
```

```json
{
  "dialog": { "close": "Cerrar" },
  "pagination": { "previous": "Página anterior", "next": "Página siguiente", "page": "Página {page}" },
  "dataTable": { "noun": { "one": "fila", "other": "filas" }, "selected": "{count} {noun} seleccionadas" }
}
```

Context passes through portals, so a dialog, menu or popover rendered into `document.body` reads
the provider above it. Toasts render where `ToastProvider` is mounted, so put `MessagesProvider`
above `ToastProvider`.

## Templates and plurals

A message is plain text, so a translation can be a JSON file and a server component can pass it to
the provider.

- **A value** goes in braces: `"Step {position} of {total}"`. Keep every placeholder the English
  has. You can move it anywhere in the sentence.
- **A count** is an object keyed by plural category: `{ "one": "{count} file", "other": "{count}
  files" }`. Use the categories your language has (`zero`, `one`, `two`, `few`, `many`, `other`).
  `other` is required. A plural you give replaces the English one whole. It is never merged, so a
  language with only `other` does not pick up English's `one`.
- **A part set in bold or kept live**, such as the range in “**26–50** of 1,284”, is a placeholder
  too. The component fills it with its element, wherever your sentence puts it.

To type a translation, use `MessagesOverride<MolaMessages>`: every key is optional, at any depth.

## The locale

`locale` on the provider sets how counts, plural categories and dates are written. Components with
their own `locale` prop (the date and time pickers, RelativeTime, NumberInput, Combobox, FileUpload)
use the provider's when theirs is not set. Without a provider, counts are written as `en-US` writes
them, on the server and in the browser alike, and dates use the browser's locale. The locale does
not translate anything by itself. The words still come from `messages`.

Direction is separate: set `dir="rtl"` on `<html>` and wrap the app in `DirectionProvider`, as
[Getting started](?path=/docs/mola-ui-getting-started--overview) shows. The layout mirrors through
logical properties, and code and ids stay left to right.

## What is not covered

- **Words you pass in.** A `title`, a `label`, a column header or an `aria-label` you give a
  component is already yours to translate.
- **Machine formats.** RunError's countdown is written as `1m 05s`, a compact format read like a
  timer, not a sentence.
