# Color

Every swatch on this page is painted from the live CSS variable, split down the middle into the
light and dark theme, and labelled with the value and ratio **computed from `tokens.css`** by the
resolver the contract test uses. If a label disagreed with its paint, the build would already be
red.

## Cloth — the grounds

Bleached cotton in the light theme; the dyed base layer in the dark one. `cloth-pale` is *raised*
in both themes — lighter on light, lighter on dark — so "raised" means the same thing either way.

## The four layers

Commercial cotton in the range a mola is actually cut from. Flat, saturated, never mixed with each
other. In the dark theme they are lifted until they carry text on the dark ground.

## Washes

A mola has no tints, so washes are reserved for a whole region that belongs to a layer without
becoming it: a callout, a selected row, a running step. Mixed thin enough that **every step of the
ink ramp stays legal on every wash**.

## Two themes, one declaration

```css
--cloth: light-dark(#edeee8, #16181c);
```

Each token is written once with both values, and `color-scheme` picks one. That buys three things
a duplicated `[data-theme=dark]` block does not: the OS preference is honoured with no script, any
subtree can flip theme on its own, and a token cannot exist in one theme and be forgotten in the
other.
