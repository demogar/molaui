# Tokens

<DecisionsBehind foundation="Foundations/Tokens" />

Every token in `src/styles/tokens.css`, the one file in the system allowed to hold a colour
literal. The table is generated from that file: the values in each theme are resolved by the same
code the contrast test runs, so a value here cannot disagree with what the test measured. The
role is the section of the file a token sits in, and its own note where the file gives one.

Copy puts `var(--name)` on the clipboard, which is how a token is used in CSS. In markup, prefer
the Tailwind utility its scope allows: `--cloth-pale` is a surface, so `bg-cloth-pale`;
`--ink-muted` is text, so `text-ink-muted`. [Color](?path=/docs/foundations-color--overview)
lists the scopes.

## Reading the values

- **A colour shows a hex in each theme.** Each one is a `light-dark()` pair, and a token that is a
  mix of two others is resolved through OKLab to the colour it paints.
- **A value that depends on what is underneath is shown as written.** A translucent mix (the
  scrim, the backdrop, a keyline on ink) has no single colour, so the resolver leaves it alone
  rather than guess.
- **Sizes and durations are the same in both themes.** The density tokens shown here are the
  comfortable values; [Spacing](?path=/docs/foundations-spacing--overview) shows what each density
  sets.

The same palette is published for design tools as W3C design tokens in `tokens/mola.tokens.json`,
both themes fully resolved, and CI fails if that file falls behind `tokens.css`.
