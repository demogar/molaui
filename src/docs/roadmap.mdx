# Roadmap

What Mola UI means to do next, what it is thinking about, and what it has decided not to do.
Nothing here has a date. A date on a roadmap is a promise, and this page would rather be
accurate than reassuring. When an item ships, it comes off this page in the same pull request,
and the [changelog](?path=/docs/mola-ui-changelog--overview) records it.

The limits of what ships today are on [Known gaps](?path=/docs/mola-ui-known-gaps--overview).
This page is about what comes after them.

## Planned

Agreed, and waiting for the work. In no particular order.

### Screen-reader passes, by hand

Every component page will be run with VoiceOver on Safari and NVDA on Firefox, and the result
written into the page's testing status. Automated checks prove roles, names and live regions are
there; only a person can say how a page sounds, and whether a long-running agent run is
announced too often or not enough. Thread's *Jump to latest*, which so far has only been tested
by script, is part of this pass.

### The rest of the Figma kit

The kit is a Figma plugin in the repository (`figma/`), generated from the tokens and the
component manifest. It writes the variables, with their scopes and code syntax, and draws the
core components, named after their code exports, with the prop names as variant axes and the
code's exact values (`danger`, `sm`). It has been tested against a fake of Figma's API. It has
not been run in a real file yet, and there is no published library. Two things are left: run it
once in Mola's own Figma file and publish that file as a library, then draw the components
`figma/component-map.json` lists as `pending`, starting with the overlays and the AI layer.

### 1.0.0

Before 1.0.0, a minor release can break things (see
[Versioning](?path=/docs/mola-ui-versioning--overview)). 1.0.0 is the release that stops that,
so it comes when the API is one we would promise to keep: the deprecations on the
[Codemods](?path=/docs/mola-ui-codemods--overview) page removed, each with its codemod, and the
screen-reader passes above done.

## Under consideration

Ideas with a reason behind them, not commitments. Each would need a
[proposal](https://github.com/demogar/molaui/issues/new?template=proposal.yml) with three use
cases before it moved up.

- **Codemods without a checkout.** A codemod runs from a clone of this repository today. A
  `mola-ui-codemod` command in the package, beside `mola-ui-mcp`, would let a product run one
  with `npx`.
- **Snippets as an editor extension.** The snippets are a file you copy into `.vscode/` today, so
  they don't update when the package does. An extension would, at the cost of something else to
  install and publish.
- **Recipes, and stories tagged by job.** A page of small, complete answers ("a form that saves",
  "a table that loads"), and story tags such as `loading` or `forms`, so the sidebar's filter
  answers the question a reader arrives with.
- **Charts beyond the sparkline.** Bar and line charts drawn with the tokens, for the dashboards
  an operations tool needs. They would have to keep the rule that state is never colour alone,
  which a series told apart by colour alone would break.
- **A high-contrast theme.** Forced colours are supported; a theme a person chooses inside the
  product, with stronger keylines and inks, is not.
- **Translated documentation**, once the components' own strings can be translated.

## Not planned

Decided, with the reason, so a proposal can start from it rather than rediscover it.

- **Rounded corners.** The radius is zero; a cut edge is square. See
  [The cut](?path=/docs/foundations-the-cut--overview).
- **A spinner.** Work in progress is shown by the working relleno, which says where the work is;
  see [Motion](?path=/docs/foundations-motion--overview).
- **Density props on components.** Density belongs to a surface and everything inside it, not to
  one control. See [Density is a surface](?path=/docs/decisions-0005-density-is-a-surface--overview).
- **Copy-and-paste distribution.** Mola UI is installed, not copied, so a fix reaches every
  product that uses it.
- **Mola motifs as decoration.** Mola UI borrows the method of the mola (layers, cut edges,
  revealed bands), never its designs. The [Introduction](?path=/docs/mola-ui-introduction--overview)
  explains why.

## How an idea gets here

1. **Propose it** with the [proposal template](https://github.com/demogar/molaui/issues/new?template=proposal.yml).
   It asks for three use cases, what exists today, the states it needs and how it fits the rules.
2. **Under consideration** while the use cases are gathered and discussed on the issue. Open
   proposals are under the [`proposal` label](https://github.com/demogar/molaui/issues?q=is%3Aissue+is%3Aopen+label%3Aproposal).
3. **Planned** once the design is agreed and the issue says who will build it.
4. **Shipped**, and off this page, in the pull request that builds it.

A proposal that reverses one of the [decisions](?path=/docs/decisions-all-decisions--overview)
needs a new decision record, which says what it replaces and why.
