# Mola UI

> A design system cut like a mola: flat layers, hard keylines, revealed bands. React components for dense internal tools and AI-native interfaces. Published as `@demogar/mola-ui`: React 19, Base UI for behaviour, Tailwind v4 for styling, design tokens as CSS custom properties.

54 components and 12 AI components (66 documented pages).

Install and set up:

```bash
npm install @demogar/mola-ui @base-ui/react @fontsource-variable/archivo @fontsource-variable/alegreya @fontsource-variable/martian-mono
```

`@base-ui/react` is a peer dependency: install it beside the package so the app and Mola share one copy. The package is ESM only; `require()` works on Node 22.12 or later.

```tsx
import '@fontsource-variable/archivo/wdth.css'
import '@fontsource-variable/alegreya/wght.css'
import '@fontsource-variable/martian-mono/wdth.css'
import '@demogar/mola-ui/styles.css'
import { Button } from '@demogar/mola-ui'
```

Mount the providers once, at the app root (in Next.js, `app/layout.tsx`):

```tsx
import { DirectionProvider, ToastProvider, TooltipProvider } from '@demogar/mola-ui'

<DirectionProvider direction="ltr">
  <ToastProvider>
    <TooltipProvider>
      <App />
    </TooltipProvider>
  </ToastProvider>
</DirectionProvider>
```

`ToastProvider` is required: `useToast()` throws without it. `DirectionProvider` gives Base UI the keyboard direction; for right-to-left, set `dir="rtl"` on `<html>` and `direction="rtl"` on the provider. `TooltipProvider` is optional.

Theme and density are attributes, not props: `<html data-theme="dark" data-density="compact">`. Leave `data-theme` off to follow the OS; a stored choice is set by an inline `<head>` script before the first paint. `styles.css` includes Tailwind's preflight and styles `body`; in an existing app, import `@demogar/mola-ui/components.css` instead, which scopes the reset to the components. Already on Tailwind v4? Import `@demogar/mola-ui/tailwind.css` into your own build instead of `styles.css`.

## Rules

- Interactive edges use `shadow-cut` (or `shadow-floating` on overlays), never `border`. `border-keyline` is for decorative dividers only. A box-shadow edge can grow a revealed band on hover without moving its neighbours, and the named utilities keep an outline in forced-colours mode.
- Radius is zero. `rounded-full` only for something that is genuinely a dot. The system is cut cloth: nothing in it is rounded.
- State is never colour alone: glyph, word and colour, in that order of importance. It has to survive colour blindness, a greyscale screenshot and forced colours.
- Disabled is stated, not faded. No `opacity-*` on a disabled control. Opacity fades the keyline and the label to about 2:1, a failure axe does not report because disabled controls are exempt.
- Colours come from tokens, each through a utility its scope allows (surface `bg-`, text `text-`, edge `border-`/`decoration-`, mark `bg-`/`fill-`). No hex, rgb or arbitrary colour values outside `tokens.css`. Every token pairing has a measured contrast ratio in both themes; a colour outside the token file, or a token outside its scope (`text-cloth-pale` compiles), was never measured.
- Theme and density are attributes (`data-theme`, `data-density`) on `<html>` or a subtree, not props or React context. Dialogs and menus portal to `<body>` and must inherit them. No component takes a density prop.
- Lay out with logical properties: `ps-`/`pe-`, `ms-`/`me-`, `inset-s-`/`inset-e-`, `text-start`/`text-end`. `dir="rtl"` then mirrors the layout with no second set of classes.
- Typefaces have roles: Archivo (`font-ui`) for the interface, Alegreya (`font-text`) for prose from a person or a model, Martian Mono (`literal`) only for machine literals. A reader can tell from the letterforms whether the product, a person or the machine is speaking.
- Labels are sentence case; buttons start with a verb and name the object (“Cancel run”, not “OK”). A button that names its consequence can be chosen without reading the surrounding text.
- Unknown duration is the relleno working state, never a spinner; elapsed time counts up instead of a progress bar inventing a percentage. Model work has no knowable total, and a bar that stalls at 90% is a lie.
- Anything that writes to the world waits for a person, with the choices given equal weight (`ToolCall` approval, `ChangeReview`). An agent’s action is only as safe as the decision in front of it.
- Use the components for behaviour. Do not re-implement focus trapping, roving focus or typeahead; the components are built on Base UI. A maintained primitive gets keyboard and screen-reader behaviour right in more cases than a local copy.
- Check a component’s lifecycle phase before building on it. Stable is covered by semver, Experimental may change in a minor release, and Deprecated names its replacement: use that instead. A screen built on a component that is about to change or go is built twice.
- Do what each component’s accessibility section leaves to you, usually an accessible name or a label. The component handles roles, focus and announcements. Axe catches a missing name only on the screens it is run on; the component cannot know what its button is for.

## Lifecycle phases

Every component has one phase. Stable unless the index says otherwise.

- Experimental: Its API may change in a minor release, without a deprecation first.
- Stable: Semantic versioning applies: nothing breaks without a deprecation first.
- Deprecated: It still works and warns in development. It will be removed; move to its replacement.

## Actions

### Button

https://demogar.github.io/molaui/?path=/docs/components-actions-button--overview

A cut-shape button for an action on this page, with IconButton for an action shown as an icon alone.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- Starting an action: run, save, delete, cancel.
- Primary for the main action of a panel, secondary for the rest, danger only for destruction, ghost for the least emphasis.
- Work in flight after a press, with loading, which keeps the label and adds the working strip instead of a spinner.
- Icon-only actions in dense rows and toolbars, with IconButton and its required label.

When not to:
- Going to another page or URL. Use a link: an a element, or your router’s link styled with buttonVariants.
- A row of related actions above a table or canvas, with one tab stop. Use Toolbar.
- More actions on one object than deserve a button each. Use Menu.
- Choosing between views, where the pressed state stays. Use Segmented control.

- Do: Keep one primary button per panel, and keep danger for actions that destroy something.
- Don’t: Use danger red for emphasis, or set several primary buttons side by side.
- Do: Let a disabled button keep its stated look, and say nearby why it is unavailable.
- Don’t: Fade a button with opacity, or disable it with no explanation.

Content:
- Start with a verb and name the object: “Delete run”, “Start run”, not “OK”, “Yes” or “Submit”.
- Write labels in sentence case with no trailing period; the button sets them in capitals itself.
- Give IconButton a label that names the action and the object, “Copy run id”; it is also the tooltip.

Keyboard:
- Tab: Moves focus to the button, including while it is loading.
- Enter or Space: Activates it, unless it is disabled or loading.

Mola handles:
- Renders a native `<button>` through Base UI, so it is announced as a button with its label as the name.
- While `loading`, sets `aria-busy`, stops accepting presses and stays focusable, so focus is not thrown back to the top of the page.
- Hides the leading icon and the arrow from assistive tech, so the label alone is the name.
- Gives `IconButton` its `label` as both the `aria-label` and the native tooltip.

You handle:
- Write a label that names the action with a verb: Deploy, Save changes.
- Give every `IconButton` a `label`; the icon is not a name.
- Use a link styled with `buttonVariants` when the control goes somewhere rather than does something.

#### `buttonVariants` (function)

A button is a cut shape, so its edge is a `box-shadow` keyline rather than a `border`. The signature hover reveals a band of the layer beneath the shape, which means the edge has to grow by several pixels without moving anything around it. A border would reflow the toolbar; a shadow does not.

Types: `ButtonProps`, `IconButtonProps`

Used in: Agent console, Form example, Agent hand-off, Confirmation, Empty states, Filtered table, List and detail, Settings page

## Data display

### Avatar

https://demogar.github.io/molaui/?path=/docs/components-data-display-avatar--overview

A person or an agent as a square tile, with initials or a glyph on a colour picked from the name.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- Showing who did something in a log, a page header or a list of reviewers.
- Marking an agent with a glyph through icon, so a person and a bot are never confused.
- Several people in one place, with AvatarGroup, which folds the rest into a “+n” tile past max.

When not to:
- Stating a status or a role. Use Badge.
- An image or chart slot that has nothing in it yet. Use Placeholder.

- Do: Pass the full name; it becomes the accessible name and seeds the colour.
- Don’t: Pass initials or a handle as the name; a screen reader then announces “AP”.

Content:
- Name people by full name and agents as people know them: “Support triage”.
- Name an AvatarGroup by role: “Reviewers”, “On call”.

Mola handles:
- Gives the tile `role="img"` and the `name` as its accessible name and tooltip.
- Hides the initials or icon from assistive tech, and gives the image an empty `alt`, so the name is read once.
- Keeps the initials until the image has loaded, so a broken URL never shows a broken-image glyph.
- Makes `AvatarGroup` a named group, and reads the overflow tile as "3 more" rather than "+3".

You handle:
- Pass the full name, not initials, as `name`.
- Give `AvatarGroup` a `label` that says who the people are: Reviewers, On call.
- Wrap the avatar in a link or button yourself if it opens a profile; it is not interactive.

### Code

https://demogar.github.io/molaui/?path=/docs/components-data-display-code--overview

Machine text: Code for an inline literal, CodeBlock for a labelled block with copy and wrap.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- An id, a field name or a flag inside a sentence, with Code.
- A tool’s arguments, a query or a log tail, with CodeBlock; JSON is tokenised by value kind.
- A payload cut off mid-stream; CodeBlock shows exactly what arrived.

When not to:
- Figures compared down a column, such as cost and duration; they are Archivo with tabular figures. Use Meta.
- A keyboard shortcut. Use Kbd.
- A proposed change to a file, shown as additions and removals. Use Change review.
- Labels, headings or emphasis; the monospace is only for text a machine reads. Use Text.

- Do: Use Code for a literal inside a sentence.
- Don’t: Break a sentence with a CodeBlock to show one id.
- Do: Turn copyable off for payloads that must not leave the page.
- Don’t: Put a CodeBlock on a black terminal panel; it sits on the same cloth as everything else.

Content:
- Show literals exactly as the system stores them; do not change their case or add spaces.
- Label a CodeBlock by its role or file name, as the reader would search for it: “arguments”, “query.sql”.

Keyboard:
- Tab: Moves focus to the wrap toggle, the copy button, then the code itself.
- Enter or Space: Toggles line wrapping, or copies the code, on the focused button.
- ArrowUp or ArrowDown or ArrowLeft or ArrowRight: Scrolls the code while it has focus.

Mola handles:
- Makes the scrolling `<pre>` focusable and names it by the block label, so the overflow is reachable without a mouse.
- Reports the wrap toggle as pressed or not pressed with `aria-pressed`.
- Announces a copy through a polite status that is always mounted, as well as turning the icon into a check.
- Pins the code body left to right in a right-to-left page, while the header mirrors.

You handle:
- Give the block a `label` that says what the code is: arguments, result, query.sql.
- Set `copyable={false}` for content that must not leave the page.

### Description list

https://demogar.github.io/molaui/?path=/docs/components-data-display-description-list--overview

Term and value pairs: the properties of a run, a document or an evaluation.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- A side panel of properties scanned top to bottom, with the inline layout.
- Values long enough to wrap, such as a system prompt or a path, with the stacked layout.
- A summary that closes a section, with the grid layout.
- Ids, hashes and model names marked literal, so they are never read as prose.

When not to:
- Many records with the same fields, compared row against row. Use Table.
- A few headline figures with their change over time. Use Stat.
- The fields of a record before and after a proposed change. Use FieldChanges.

- Do: Mark ids and model strings literal, and leave prose and figures in the system voice.
- Don’t: Set every value in the monospace.

Content:
- Terms are short nouns in sentence case, without colons: “Model”, “Duration”.
- Give values their units, “41s”, “$0.2185”, and show a status as a Badge rather than a bare word.

Mola handles:
- Renders a real `<dl>` with each `<dt>` and `<dd>` pair grouped in a `<div>`, so terms and values are read together.
- Sets values marked `literal` in the machine face, so an id is not mistaken for prose.

You handle:
- Write terms as short nouns, and keep each value to the fact it names.
- Put a heading above the list; it has no name of its own.

### Stat

https://demogar.github.io/molaui/?path=/docs/components-data-display-stat--overview

A KPI tile: a label, a figure, a change with its direction and sentiment, and an optional sparkline.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- Headline figures at the top of a page, grouped in a StatGroup cut from one panel.
- A change whose direction and meaning differ, such as latency going down being good news.
- The shape of the recent past as a sparkline beside the figure.

When not to:
- A reading against a limit or threshold, such as a quota. Use Meter.
- Many properties of one object. Use Description list.
- A trend that needs axes, values or several series. A sparkline is a glyph; use a chart.

- Do: State direction and sentiment separately, so cost going down reads as good.
- Don’t: Assume up is green; latency going up is a regression.

Content:
- The label names the measure and its window: “Runs today”, “p95 duration”.
- Put the unit in unit, “%”, and the comparison in the delta’s period, “vs yesterday”.
- Group digits and keep only the precision a reader uses: “1,204”, “97.8”.

Mola handles:
- Renders each tile as a `<dt>` and `<dd>` pair, inside one `<dl>` for a `StatGroup` or its own `<dl>` when alone.
- Reads the delta as one sentence, "Up 12%, vs last week, an improvement", and hides the arrow and the separate parts.
- Carries direction in the arrow and sentiment in the colour, so neither depends on colour alone.
- Hides the sparkline from assistive tech, because the figure and the delta already say what it shows.

You handle:
- Set `sentiment` on every delta; the tile does not guess that up is good.
- Give the comparison in `period` so the change has something to be measured against.

Anatomy:
- Tile (`[data-slot="stat"]`): A raised cloth tile with a keyline; inside a Stat group, the group draws it.
- Label (`[data-part="label"]`): What is measured, in the label register.
- Value (`[data-part="value"]`): The figure, in the display face with tabular numerals.
- Trend (`[data-part="trend"]`): A decorative sparkline; the last point is a cut square.
- Delta (`[data-part="delta"]`): Direction as a glyph, sentiment as a colour, and both in a sentence for screen readers.
- Unit (`[data-part="unit"]`): The unit, muted, kept on the figure’s line in either direction.
- Hint (`[data-part="hint"]`): One line of context: a budget, when it was last synced.

#### `Sparkline` (component)

An ink polyline — no fill, no gradient, no axis. A sparkline is the shape of the recent past and nothing more; the moment it grows a gridline it is a chart pretending to be a glyph. The last point is a square cut out in rojo (it is the "now" the figure beside it states), drawn as a square because a blade does not cut circles.

### Swatch

https://demogar.github.io/molaui/?path=/docs/components-data-display-swatch--overview

A small decorative colour key, square or round, in one of the badge tones, placed before the word it keys.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- A legend entry that ties a word to the colour of map pins, chart series or rows.
- A marker before a group heading or a filter label, so it reads in the same colour as what it filters.
- Round only when the thing it keys is itself a dot, such as a map pin.

When not to:
- The state of a row or an object, or a mark that must be announced on its own. Use StatusDot.
- A short aside with a coloured marker before its title. Use Callout.

- Do: Put the word beside every swatch; the swatch is hidden from screen readers.
- Don’t: Let a row of coloured squares stand in for a legend.
- Do: Use tone="accent" when the key must match a gold field exactly.
- Don’t: Paint a swatch with bg-oro by hand; on light cloth it falls below 3:1.

Mola handles:
- Is always `aria-hidden`, so it can never be the only carrier of a meaning.
- Paints itself in the system text colour in forced colours mode, so the key stays visible.

You handle:
- Put the word the colour stands for beside the swatch.

- `size`: `sm`, `md` (default `md`)
- `shape`: `square`, `round` (default `square`)

A colour key: the small square before a legend entry, a filter chip's label or a flat callout's title, that ties the words to a colour used elsewhere — map pins, a column of urgencies, a chart series.

### Table

https://demogar.github.io/molaui/?path=/docs/components-data-display-table--overview

Table primitives for rows of records, and DataTable for columns as data with sorting, selection, column visibility and pages.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- Comparing many records with the same fields, such as runs, documents or evaluations.
- Sorting, selection, bulk actions and pages on client or server data, with DataTable.
- A layout DataTable does not cover, such as virtualised rows, with the primitives.

When not to:
- The properties of one record. Use Description list.
- Events where the order is the content. Use Timeline.
- A handful of headline figures. Use Stat.

- Do: Right-align numeric columns, header included, in tabular figures.
- Don’t: Left-align costs and durations, or set them in the monospace.
- Do: Show the no-results empty row with Clear filters when filters hide every row.
- Don’t: Tell someone to create their first run when a filter is hiding the runs they have.

Content:
- Headers are short nouns in sentence case: “Run”, “Started”, “Cost”.
- Show a value that does not exist yet as an em dash, “—”, not as zero.
- Set noun so counts read naturally: “3 runs selected”.

Keyboard:
- Tab: Moves focus to the sort buttons, the row checkboxes and the other controls in turn.
- Enter or Space: Sorts by the focused column header.
- Space: Selects or clears the focused row checkbox, or every row on the page from the header box.
- ArrowUp or ArrowDown or ArrowLeft or ArrowRight: Scrolls the table frame when it overflows and has focus.
- Escape: Closes the column menu and returns focus to the Columns button.

Mola handles:
- Puts the scrolling frame in the tab order only when the table overflows it.
- Sets `aria-sort` on the sorted column only, and `aria-selected` on selected rows.
- Uses native checkboxes, and announces the selection count once through a polite status.
- Marks a loading `DataTable` with `aria-busy` and hides its skeleton rows from assistive tech.

You handle:
- Name the table with `label` or `aria-label`, or a `caption`.
- Give `rowLabel` so each row checkbox says which row it selects.
- Mark figure columns `numeric`, on the header and the cells alike.

Anatomy:
- Frame (`[data-slot="table-frame"]`): Scrolls the table in both directions, and joins the tab order when it overflows or has a sticky header.
- Column header (`[data-part="head"]`): The label register on an ink rule; a sort control when sortable.
- Row (`[data-part="row"]`): A row at the density’s row height, with a soft keyline under it.
- Footer (`[data-part="footer"]`): Totals, on a shaded ground under an ink rule.
- Caption (`[data-part="caption"]`): What the table shows, under it, read by screen readers as its name.

### Callout

https://demogar.github.io/molaui/?path=/docs/components-feedback-callout--overview

A message that belongs to a region of the page, with a tone, an optional title and actions.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- A standing condition of a page or panel: a model that retires soon, a read-only workspace, a stale index.
- Something to read before working in the region, with one or two actions.
- A notice the person can dismiss, with onDismiss, where the caller decides whether it returns.
- A one-line aside beside a hero or at the head of a list, with variant="flat": the wash and a swatch, no seam, and it keeps its own height in a grid.

When not to:
- Something that has just happened, possibly elsewhere, such as a finished re-index. Use Toast.
- A decision the person must make before going on. Use AlertDialog.
- A panel with nothing to show. Use Empty state.
- A short status on a row. Use Badge.

- Do: Match the tone to the consequence: warn for a limit approaching, danger for something broken.
- Don’t: Use danger for news or tips; red has to keep meaning broken.
- Do: Put a callout that appears after an action inside a live region, or use a toast.
- Don’t: Insert a static callout after an action and expect a screen reader to notice it.

Content:
- The title states the condition: “Token budget at 86%”, not “Warning” or “Heads up”.
- The body says what it means and what to do: “Switch the model in settings to keep evaluation history comparable.”
- Actions are verbs on the object: “Retry from 812”, “View log”.

Keyboard:
- Tab: Moves focus to the dismiss button, when `onDismiss` is set.
- Enter or Space: Dismisses the callout.

Mola handles:
- Becomes a region named by its title when it has one, and stays out of the landmark list when it does not.
- Renders the title as a real heading at `headingLevel`.
- Hides the seam, the icon and the swatch from assistive tech; the title and body carry the tone in words.
- Names the dismiss button "Dismiss".

You handle:
- Choose a `headingLevel` that fits the page outline.
- Render a callout that appears in response to an action inside a live region, or use a toast.
- Move focus somewhere sensible after a dismiss, because the button that had it is gone.

Anatomy:
- Container (`[data-slot="callout"]`): The tone’s wash, bounded by the ink keyline like every cut shape.
- Seam (`[data-part="seam"]`): The relleno along the top edge: the tone as a cut-back layer, not a coloured side bar.
- Icon (`[data-part="icon"]`): The tone’s glyph, so the tone is never colour alone.
- Title (`[data-part="title"]`): A real heading; it also names the region.
- Body (`[data-part="body"]`): The message. Never coloured: the tone owns the region, not the reading column.
- Actions (`[data-part="actions"]`): Usually one secondary button at the small size.
- Dismiss (`[data-part="dismiss"]`): Present only with onDismiss; the caller decides whether it comes back.

### Empty state

https://demogar.github.io/molaui/?path=/docs/components-feedback-empty-state--overview

- The title states the condition: “No runs match these filters”, “Traces did not load”.

- Seam (`[data-part="seam"]`): The tone’s relleno along the top, on error and no-permission only.

- Icon (`[data-part="icon"]`): A small ink square with the variant’s glyph. Not an illustration.
- Title (`[data-part="title"]`): What state this is, as a heading.

### Skeleton

Bones in the shape of content that has not arrived, with SkeletonGroup to mark the region busy and say once what is loading.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- A card, list or table whose layout is known while its data loads.
- Swapping bones for content in place, so the layout barely moves when the data lands.
- Lines of text that follow the surrounding type size, with SkeletonText.

When not to:
- Work with a known size, such as an upload. Use Progress.
- A slot whose content does not exist yet, rather than one that is loading. Use Placeholder.
- A button waiting on its own action; give it its loading state. Use Button.
- Text a model is still writing. Use Streaming text.

- Do: Wrap the bones in SkeletonGroup with a label, so the region is announced once.
- Don’t: Add a spinner or a “Loading…” line to each bone; the system has no spinner, by design.
- Do: Cut the bones to the content’s shape: an avatar bone, a short line for a name.

### Toast

https://demogar.github.io/molaui/?path=/docs/components-feedback-toast--overview

A floating notice for something that happened elsewhere or just now; a running toast turns into its result in place.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- Confirming an action whose result is not visible where the operator is.
- Long work the operator may leave, with toast.running, then toast.update with the outcome.
- One follow-up action, such as Undo or View run.

When not to:
- A condition of the page that stays true, such as read-only mode. Use Callout.
- Anything that needs a decision, or more than one action. Use Dialog.
- A validation error on a field. Use Field.
- Confirming a copy to the clipboard. Confirm it in place, as CodeBlock and Message do.

- Do: Update the running toast with the outcome, so the result lands where the work was.
- Don’t: Leave the running toast and fire a second, unrelated success toast.

Content:
- The title states what happened, in the past tense: “Index rebuilt”, “Deploy failed”.
- The description adds the cause or the figures: “1,204 documents · 3m 41s”.
- The action is one verb: “Undo”, “Retry”, “View”.

Keyboard:
- F6: Moves focus to the toast region and pauses the timers.
- Tab: Moves through the toasts and their action and dismiss buttons.
- Enter or Space: Runs the action, or dismisses the toast, on the focused button.
- Escape: Closes the toast that has focus.
- Shift+Tab: Leaves the region from its start and returns focus to where it was.

Mola handles:
- Renders the stack in a polite live region, and announces `danger` toasts assertively.
- Prefixes the title with hidden words for its tone: Success, Error, In progress.
- Pauses the timers while the region has keyboard focus, and keeps a running toast until it is updated or dismissed.
- Names the dismiss button "Dismiss".

You handle:
- Mount `ToastProvider` once, near the root.
- Write a title that says what happened without the page around it.
- Use a dialog for anything the person must answer; a toast can be missed.

### Chip

https://demogar.github.io/molaui/?path=/docs/components-forms-chip--overview

A filter chip with a real checkbox or radio inside, filled with ink when on, with an optional count.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- Filters above a list or table that apply as they are pressed.
- Showing how many rows each filter would leave, with count.
- One of a few fixed ranges, such as 1h, 24h and 7d, with type set to radio.

When not to:
- A status shown to the reader rather than chosen by them. Use Badge.
- Switching between views of the same data. Use Segmented control.
- Options in a form that is saved later. Use Checkbox.

### Combobox

https://demogar.github.io/molaui/?path=/docs/components-forms-combobox--overview

### Date picker

https://demogar.github.io/molaui/?path=/docs/components-forms-date-picker--overview

DatePicker for one date, typed or picked from a calendar; DateRangePicker for a period, with presets and two typed ends.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- One date, such as when to run an evaluation, with DatePicker.
- A period for a report or a filter, with DateRangePicker and presets such as the last 7 days.
- Dates with bounds or unavailable days, through min, max and isDateDisabled.

When not to:
- A period between two dates, where two single pickers would not check the order. Use DateRangePicker.
- One date; a range picker would ask for a second press. Use DatePicker.
- A duration, such as a timeout in seconds. Use Number input.
- A few fixed relative ranges, such as 1h, 24h and 7d. Use Chip.

- Do: Pass locale, so the typed order, digits and first day of the week follow it.
- Don’t: Guess the date order from the language; es-ES and es-PA write dates in different orders.
- Do: Keep typed entry on in DateRangePicker; typing is the accessible path into a date.
- Don’t: Turn typedEntry off unless the presets and the grid cover every case.

Content:
- Label the field by what the date is for: “Run evaluation on”, “Report period”.
- Leave the placeholder to the component; it is the locale’s own pattern.
- Rules the picker cannot know, such as required, go to Field as an instruction: “Choose a date for the evaluation.”

Keyboard:
- Tab: Moves focus to the date input, then to the calendar button.

- Escape: Closes the calendar without changing the value and returns focus to the button.

- The calendar is a `grid` named by its month heading, with one tab stop; the day carries `aria-selected`, today `aria-current="date"`, and an unavailable day says so in its name.

- The calendar button is named by the value, “Change date, 6 October 2026”, and focus returns to it when the calendar closes.

You handle:
- Name it: put it in a `Field`, or pass `aria-label`.
- State rules the picker cannot know, such as “required”, through `Field`’s `error`.

### Field

https://demogar.github.io/molaui/?path=/docs/components-forms-field--overview

A label, a control and a hint or error wired together; the page also covers Input, Textarea, SearchInput and Label.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- Any form control that needs a visible label, a hint and a validation message, through the render prop.
- One line of text with Input, with a unit or an icon inside the field through leading and trailing.
- Several lines with Textarea, which grows with its content when autosize is set.
- Filtering a list with SearchInput, which shows a shortcut cap when empty and a clear button when not.

When not to:
- A number that is stepped, bounded or formatted. Use Number input.
- A choice from a known list. Use Select.
- A date or a period. Use Date picker.
- A prompt to a model, with attachments and a send button. Use Prompt input.

- Do: Spread the control props onto the control, so its id, description and invalid state are wired.
- Don’t: Use the placeholder as the label; it disappears as soon as someone types.
- Do: Put the unit inside the field with trailing: “seconds”, “tokens”.
- Don’t: Write the unit as text after the field, where it reads as a second field.

Content:
- Labels are short nouns in sentence case: “Run name”, “Webhook URL”.
- Hints explain the consequence: “Shown in the run list and in alerts.”
- Errors say what is wrong and how to fix it: “Must be between 1 and 900 seconds.”

Keyboard:
- Tab: Moves focus to the control.
- Enter or Space: On a search field’s clear button, empties the field and returns focus to it.

Mola handles:
- `Field` links the label to the control and joins the hint and error into `aria-describedby`, in the order they are shown.
- An error sets `aria-invalid`, is announced with `role="alert"`, and carries a cut square so it is not colour alone.
- The required asterisk is hidden from assistive technology while `required` reaches the control; “Optional” is kept as a separate word.
- `SearchInput` is a `searchbox`, and its clear button is named “Clear search”.

You handle:
- Spread the `control` props onto the control; without them it has no name and no description.
- When several fields fail at once, add an error summary at the top of the form and move focus to it.
- Bind the key shown by `shortcut` yourself; the key cap is display only.

Anatomy:
- Label (`[data-part="label"]`): Names the control, in the label register, and is wired to it with htmlFor.
- Label aside (`[data-part="label-aside"]`): A count or a default beside the label; never a second label.
- Hint (`[data-part="hint"]`): States the rule. It stays when an error arrives, and is read first.
- Error (`[data-part="error"]`): Says how this value broke the rule. Announced on insertion, and marked with a cut square so it is not colour alone.

https://demogar.github.io/molaui/?path=/docs/components-forms-slider--overview

A value or a range on a continuous scale, with the value always printed in tabular figures.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- A value where the range matters as much as the number, such as temperature or a rollout percentage.

- Don’t: Turn showValue off, so the value can only be learned by dragging.

- End labels describe the effect at each end, not the number: “Precise”, “Creative”.

- PageUp or PageDown: Changes by `largeStep`.
- Home or End: Jumps to `min` or `max`.

Mola handles:
- Base UI renders a real `<input type="range">` in each thumb, with `role="slider"` and the value in `aria-valuenow` and `aria-valuetext`.
- The `label` names every thumb.
- The value is printed beside the label, so it is never learned only by dragging.

You handle:
- Give it a `label`; without one the thumb has no name.
- The `minLabel` and `maxLabel` are hidden from assistive technology; if they carry meaning, say it in text near the slider.

### Toolbar

https://demogar.github.io/molaui/?path=/docs/components-layout-toolbar--overview

A row of related controls with one tab stop and arrow-key movement, with toggles, a field and an overflow menu.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- Actions and filters above a table or canvas, such as Re-run, Stop and Share trace.
- Pressed states, with ToolbarToggle and ToolbarToggleGroup.
- A filter field in the row, with ToolbarInput and an aria-label.
- More actions than fit, folded into a More menu with ToolbarOverflow.

When not to:
- One or two actions; plain buttons are enough. Use Button.
- Switching between views. Use Segmented control.
- Actions on one row of a table. Use Menu.

- Do: Separate groups with ToolbarSeparator.
- Don’t: Group with extra space; between identical ghost buttons it reads as uneven spacing.
- Do: Order overflow items by priority, with the destructive action last.
- Don’t: Put Delete first, where it stays in the row the longest.

- Name the toolbar with aria-label: “Run actions”, “Filter runs”.

- Shift+Tab: Leaves the toolbar; it is one tab stop.

- Renders `role="toolbar"` with roving focus from Base UI, so ten controls are one tab stop.

- Removes overflowed actions from the row and puts them in a More menu, so the arrows never stall on a hidden control.

You handle:
- Name the toolbar with `aria-label`, and each toggle group too.
- Give a `ToolbarInput` an `aria-label`; the placeholder is not a name.
- Give icon-only buttons an `aria-label`.

### Tabs

https://demogar.github.io/molaui/?path=/docs/components-navigation-tabs--overview

### Dialog

https://demogar.github.io/molaui/?path=/docs/components-overlays-dialog--overview

Dialog for a short modal task; AlertDialog to confirm an action that destroys something.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- A short task the person finishes or cancels before going back, such as renaming an agent.
- Read-only detail that needs the screen for a moment, with only the body scrolling.
- Confirming a destructive action with AlertDialog, which opens on Cancel and ignores clicks outside.
- An irreversible action at scale, with confirmationText set to the resource’s exact name.

When not to:
- Details beside the work that the person compares with the page. Use Drawer.
- A small panel anchored to a control, without trapping focus. Use Popover.
- A notice that needs no decision. Use Toast.
- A change an agent proposes for a person to review. Use Change review.

- Do: Name the object and the consequence in a destructive confirm: “Its trace, tool calls and outputs are removed for everyone.”
- Don’t: Ask “Are you sure?” over OK and Cancel.
- Do: Return a promise from onConfirm, so the dialog stays open if the work fails.
- Don’t: Close the dialog before the work has succeeded.
- Do: Say why a confirm failed in AlertDialog’s `error`, starting with what did not happen: “Not deleted. The trace store didn’t answer.”
- Don’t: Put the failure in `description`, or close the dialog and report it in a toast.
- Do: Pass `finalFocus` when the confirm removes its own trigger, pointing at the next item or the list’s heading.
- Don’t: Keep a disabled button in place only so focus has somewhere to return.

Content:
- Titles name the task or ask the question: “Rename agent”, “Delete this run?”.
- The confirm button repeats the verb and object: “Delete run”, never “OK” or “Yes”.
- An error starts with what did not happen, then why, then what is still true: “Not revoked. … The key still works.”
- The footer holds a ghost Cancel and one primary action.

Keyboard:
- Enter or Space: On the trigger, opens the dialog and moves focus into it.
- Tab or Shift+Tab: Moves through the dialog’s controls; focus stays inside.
- Escape: Closes the dialog and returns focus to the trigger, or to `finalFocus` when it is set.
- Enter: In an alert dialog’s confirmation field, confirms once the text matches.

Mola handles:
- Base UI traps focus, locks scroll, makes the page inert and returns focus on close.
- The dialog is named by `title` and described by `description`, and a named Close button is always rendered unless `hideClose` is set.
- `AlertDialog` is a `role="alertdialog"` that an outside click does not dismiss, and it focuses Cancel first.
- While an async confirm is pending, both buttons stop taking presses and the dialog cannot be closed.
- An AlertDialog `error` is a `role="alert"`, announced once when it appears and again after each failed retry, and it is the confirm button’s description.

You handle:
- Write a `title` that names the task; it is the dialog’s name.
- Set `hideClose` only when the footer has its own way out.
- Give the confirm button the verb, “Delete run”, never “OK”.
- Set `error` when a confirm fails, and clear it when the dialog opens for something else.
- Set `finalFocus` when the confirm removes the trigger, so focus lands on the next item rather than the top of the page.

### Run status

https://demogar.github.io/molaui/?path=/docs/ai-run-status--overview

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- The state of any unit of model work: queued, running, streaming, needs approval, succeeded, failed, cancelled or timed out.
- Elapsed time that keeps counting for open work, or a fixed duration for finished work.
- Status in a header, in the label register, or in a row or sentence with register set to inline.

- Don’t: Invent a ninth status such as “Rate limited”; it is a reason on a failed run, said in words.

- Every status is a glyph, a word and a colour; the glyphs differ in shape, and the glyph is hidden from screen readers.

- Announce a change of status yourself where it matters; `RunStatus` is not a live region.

- Glyph (`[data-part="glyph"]`): A cut square whose fill and mark differ per status, so status survives greyscale.

- Duration (`[data-part="duration"]`): Elapsed time, ticking while the run is open, fixed once it ends.

Work is over and will not change again without a retry.

#### `formatDuration` (function)

`0.4s`, `12.4s`, `4m 07s`, `1h 02m`. One decimal under a minute because that is where tenths change a decision; whole units above it because nobody cancels a 4-minute run over a tenth of a second. Seconds are zero-padded past the first minute so a ticking clock never changes width — the figure is set tabular, and a `4m 7s` → `4m 10s` jump would still shift the row.

#### `useElapsed` (hook)

Milliseconds since `startedAt`, ticking while the work is still open.

Types: `RunStatusProps`, `RunStatusValue`

Used in: Agent hand-off

### Sources

https://demogar.github.io/molaui/?path=/docs/ai-sources--overview

Inline citation markers and the numbered list of sources they point to, with a preview card on hover, focus or first tap.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- An answer makes claims drawn from documents, and readers need to check them where they are made.
- Listing what each source is, where it lives, the passage used and when it was read.
- Rendering [n] markers in streamed text, with citationRenderer built from the same array as the list.

When not to:
- Ordinary links in running text that are not evidence for a claim. Use Prose.
- Saying how strongly the sources support the answer. Use Confidence.
- A tool’s raw result, such as the rows a query returned. Use Tool call.

- Do: Build the renderer once from the sources array, so marker 2 always opens source 2.
- Don’t: Number markers and list items separately; one mismatch sends the reader to the wrong document.
- Do: Include the passage the answer used and when it was read.
- Don’t: List only a title and a link; checking one sentence then means opening every document.

Content:
- Use the document’s own title as the source title, not its URL or file name.
- Quote the passage exactly as retrieved; do not paraphrase it.
- Give the domain as people know it: “docs.cayuco.internal”.

Keyboard:
- Tab: Moves to a citation marker and opens its preview card, or to a source card in the list.
- Enter: Follows the focused marker to its source card, or opens the focused source in a new tab.
- Escape: Closes the preview card.

Mola handles:
- A marker is a link named “Source 2:” and the source’s title, not “2”.
- The preview card opens on keyboard focus as well as hover, and repeats the list card, so missing it loses nothing.
- Links that open a new tab say so to screen readers, and the arrow glyphs are hidden from them.

You handle:
- Pass `source` or `title` to each `Citation`, or the marker is named only by its number.
- Render the `SourceList` on the same page under a heading, so `#source-n` has somewhere to land.

### Streaming text

https://demogar.github.io/molaui/?path=/docs/ai-streaming-text--overview

A model’s answer arriving a token at a time, in the reading voice, without layout shift, and announced once when it ends.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- Rendering an assistant’s answer as it streams, with a block caret at the end.
- Paragraphs, lists, code blocks, inline code and [n] citation markers from a model.
- Text the reader may skim, such as reasoning, with tone set to muted.

When not to:
- Long-form markup that does not stream, such as rendered documentation. Use Prose.
- Text the system says in its own voice, such as labels and hints. Use Text.
- Saying that work is under way before any text exists, outside a message. Use Run status.

- Do: Append to text as tokens arrive and pass status, so completion is announced once.
- Don’t: Wrap the text in a live region; a screen reader would read every token aloud.
- Do: Pass a stable renderCitation, built once at module scope or with useMemo.
- Don’t: Create the renderer inline on every render; finished blocks then render again on every token.

Content:
- Override doneAnnouncement only with a short, complete sentence: “Summary complete.”

Mola handles:
- The text is `aria-busy` while it streams, so it is not read token by token.
- A polite status says “Response complete.” or “Response stopped with an error.” once, when a running stream ends, and not on mount.
- The caret is hidden from screen readers, and under reduced motion it stops blinking.

You handle:
- Set `doneAnnouncement` when “Response complete.” is not the right words for what finished.
- Name the citations you render through `renderCitation`; `Citation` does this from the source’s title.

#### `Caret` (component)

The block caret: ink, half an em wide, the height of the x-height plus ascenders. A thin bar caret reads as a text field waiting for input; a block reads as output being written, which is the opposite thing.

| `errorAnnouncement` | `string` | `Response stopped with an error.` | Spoken once when a stream that was running fails. |

| `status` | `StreamStatus` | `done` |  |
| `tone` | `"default" \| "muted"` | `default` | `muted` for text the reader may skim — reasoning, not the answer. |

You handle:

### Tool call

https://demogar.github.io/molaui/?path=/docs/ai-tool-call--overview

One tool invocation: the tool’s literal name, its arguments, the result or error, and an approval when a person must decide.

Phase: Stable. Semantic versioning applies: nothing breaks without a deprecation first.

When to use:
- Showing what the model asked a system to do, with what, and what came back.
- Holding a call that writes, spends or sends until a person approves or denies it.
- Calls the model made at the same time, grouped with ToolCallGroup.

When not to:
- A larger change to files or records that needs a diff and a reason. Use Change review.
- The whole run the calls belong to. Use Agent run.
- A payload shown on its own, outside a call. Use CodeBlock.

- Do: Say in the approval reason what the call changes and whether the agent can undo it.
- Don’t: Ask for approval with no reason, or make Approve the primary button and Deny a link.
- Do: Pass args and result as objects, so they render as formatted JSON.
- Don’t: Rewrite payloads as prose; operators inspect them and paste them into tickets.

Content:
- The title says what the call is for, “Rollout results”; the name stays exactly as the model called it.
- Name approval buttons by the action: “Approve rollout” and “Deny”, not “Yes” and “No”.
- Keep the approval reason to a sentence or two: what changes, for whom, and whether it can be undone.

Keyboard:
- Tab: Moves to the call’s header, then to Approve, Deny, Retry call and the payload’s buttons when open. A call that waits for approval or has failed is held open, so its header is not a stop.
- Enter or Space: Opens or closes the call from its header, or activates the focused button.
- ArrowUp or ArrowDown or ArrowLeft or ArrowRight: Scrolls a focused arguments or result block.

Mola handles:
- The header is a button with `aria-expanded`, and a failed call or one waiting for approval opens itself.
- A failure is an alert with the error verbatim, except inside an `AgentRun` that has already raised it.
- Status is a glyph, a word and a colour, and Approve and Deny are buttons of the same weight.
- `ToolCallGroup` is a group named “N tools in parallel”, or by its `label`.

You handle:
- State in `approval.reason` why a person must approve, in words.
- Pass a `title` in words when the tool’s name alone does not say what the call is for.

Anatomy:
- Container (`[data-slot="tool-call"]`): A keylined card. While it waits for a person it wears the gold band, revealed by the cut.
- Header (`[data-part="header"]`): The disclosure trigger. A waiting or failed call is held open, so its trigger is inert.
- Tool name (`[data-part="name"]`): The identifier exactly as the model called it, as a machine literal.
- Title (`[data-part="title"]`): What the call is for, in words.
- Status (`[data-part="status"]`): A Run status: glyph, word and colour, and the elapsed time when known.
- Body (`[data-part="body"]`): The approval or the error first, then the arguments and the result.
- Approval (`[data-part="approval"]`): Why a person has to decide, and two buttons of equal weight.
- Progress (`[data-part="progress"]`): Working relleno along the top edge while the call runs.
- Error (`[data-part="error"]`): What failed, the error verbatim, and Retry. A failed call is held open.
